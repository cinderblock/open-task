# Self-update and build identity

> **Status:** active · **Started:** 2026-09-28 · **Branch:** `self-update`, worked in the
> worktree `.claude/worktrees/self-update` (excluded locally via `.git/info/exclude`)

## Goal

The app could not say which build it is, and could not update itself: `ot-update` was a
two-line placeholder, there was no `--version`, and the exe had no version resource.
The installed copy in Program Files on the dev machine said "0.2.1" in Add/Remove
Programs but was really a local `master` build, with no way to tell which commit.

User, 2026-09-28: "build it all. Use tags like "v0.1.0" (semver) to release new
versions. dirty/non tagged builds get the hash (and a -dirty suffix) as needed. the
version number on the app should also be a button to check for updates and to apply
the update if it downloads a new one".

## Decisions already made (don't re-ask)

1. **Releases are `vX.Y.Z` tags (semver).** Unchanged from before; the release workflow
   already refuses a tag that differs from the Cargo version.
2. **Build version string** (user's rule): an exact, clean tag builds as `0.2.1`.
   Anything else carries the hash, git-describe style: `0.2.1-19-g892159c`, plus
   `-dirty` for uncommitted changes (`0.2.1-0-g892159c-dirty` on a dirty tag). Shown with
   a leading `v` in the UI and `--version`. No git at build time falls back to the Cargo
   version, with a build warning.
3. **The version on the rail is the update button.** Click: check, and if a newer
   release exists, download and verify it. Click again when it is ready: install. The
   Settings page repeats it with room for the details, since the compact rail shows
   icons only.
4. **Signing happens in CI** (user choice, 2026-09-28, over local signing). The minisign
   secret key is a GitHub Actions secret, `MINISIGN_SECRET_KEY`; the release workflow
   signs `SHA256SUMS` and publishes. Known and accepted: this protects downloads from
   tampering in transit or storage, **not** against someone who can push to the repo.
5. **The key has no password** (user choice). Generated by Claude with minisign 0.12
   (`-W`), secret at `%USERPROFILE%\.minisign\open-task.key` on the dev machine, public
   key committed as `minisign.pub` at the repo root.
6. **Check-and-notify by default; downloading on its own is opt-in** (from the parent
   plan). Installing always takes a click, because it closes the app and, for the
   per-machine install, shows a UAC prompt.
7. **Updates install through the installer**, only for a copy the installer put there
   (the running exe is in the `InstallLocation` of the Inno uninstall key, HKLM or
   HKCU). Any other copy (zip, `cargo install`, a dev build) is told a release exists
   and offered the release page, never overwritten in place.
8. **The rail shows the short form** (Claude's call, 2026-09-28): `v0.2.1` for a
   release, the commit for anything else (`25c2e9c-dirty`), because the full describe
   string does not fit the 184 DIP rail. The Settings card, `--version`, the log and
   the exe's ProductVersion carry the full string.
9. **"Install updates automatically" installs when open-task closes** (user,
   2026-09-28: "have a settings option for automatic updates too"; when is Claude's
   call). Off by default. Never a restart while it runs: that would lose the history
   it has gathered, and a task manager is often left open for days. The close hides
   the window and keeps the process until Setup's Restart Manager ends it, so the
   installer stays locked through elevation. The switches chain: install needs
   download needs check. A close from logoff, shutdown or Restart Manager never
   installs.

## Design

### Build identity (`crates/ot-app/build.rs`)

- `git describe --tags --match "v[0-9]*" --long --dirty --abbrev=7` gives
  `v0.2.1-19-g892159c[-dirty]` uniformly; formatted per decision 2. No reachable tag
  (a shallow clone): `<cargo version>-g<hash>[-dirty]`. No git: the Cargo version.
- `cargo:rustc-env=OT_VERSION=...` for the binary.
- Re-runs when `.git/HEAD`, the branch ref, `packed-refs`, `refs/tags`, the index, or
  anything under `crates/`, `Cargo.toml`, `Cargo.lock` changes, so `-dirty` stays true
  for source edits. (A README-only edit does not flip it until the next source change.)
- Windows MSVC targets: a `VERSIONINFO` resource written as a `.res` file by the build
  script itself (no `rc.exe`, no crate) and handed to `link.exe`, which converts `.res`
  inputs itself. FileVersion `0.2.1.19` (4th part = commits since the tag),
  ProductVersion = the full string, `VS_FF_PRERELEASE` unless it is a clean tag.

### Updater (`crates/ot-update`)

- **Feed, no GitHub API, no JSON:** everything trusted is signed.
  1. GET `https://github.com/cinderblock/open-task/releases/latest/download/SHA256SUMS.minisig`.
     `latest` skips drafts and prereleases.
  2. Its trusted comment names the release: `open-task v0.3.0`. Unverified at this
     point; only used (after a character check) to build the next URL.
  3. GET `.../releases/download/v0.3.0/SHA256SUMS`, verify the signature with the
     compiled-in key. Now the trusted comment is authentic too; parse the version.
  4. Offer it only if it is newer than the running build (see ordering below).
  5. Download `open-task-v0.3.0-windows-setup.exe` (named in the signed sums), check
     its SHA-256 against the sums.
- **Version ordering:** a dev build `0.2.1-19-g…` is newer than `0.2.1` and older than
  anything above it, so it is offered `0.2.2` but never `0.2.1`. Semver prerelease
  precedence for tags such as `v0.3.0-pre.1`.
- **Crates:** `minisign-verify` (by minisign's author, no deps), `sha2`. HTTP is
  WinHTTP through the `windows` crate (system proxy, OS certificate store, no TLS
  stack in the binary). Other platforms report "not supported yet".
- **Build-time overrides for testing:** `OT_UPDATE_FEED` and `OT_UPDATE_PUBLIC_KEY`
  (read with `option_env!`). They only affect a binary someone builds themselves.
- **Install:** `ShellExecuteExW("open")` on the verified installer (not `runas`: Inno
  elevates itself, which is what makes `runasoriginaluser` relaunch the app
  unelevated), with `/SILENT /SUPPRESSMSGBOXES /NORESTART /CLOSEAPPLICATIONS
  /NORESTARTAPPLICATIONS /RELAUNCH=1` and `/ALLUSERS` or `/CURRENTUSER` to match the
  install. Inno closes the running app with Restart Manager (`WM_QUERYENDSESSION` /
  `WM_ENDSESSION`), installs, and its `[Run]` entry, gated on `/RELAUNCH=1`, starts
  the new version as the original user. A worker waits on Setup; if it exits while the
  app is still alive, the install did not happen and the status says why.
- **The downloaded installer is held open** with share mode read-only from before
  verification until Setup has exited, so nothing can swap it between the hash check
  and the elevated run.

### UI (`ot-ui`, `ot-shell-win`)

- Rail: an item above Settings. Expanded: an update icon, the version, and a status
  line ("Check for updates", "Checking…", "Up to date", "Downloading v0.3.0… 45%",
  "Update to v0.3.0", "Installing v0.3.0…", failures). Compact: the icon, with an
  accent dot when an update is available or ready.
- Settings: an "Updates" section: the same button as a card with a sentence of detail,
  "Check for updates automatically" (on), "Download updates automatically" (off).
- Shell: `Updater` in the window state; worker results come back as `WM_APP_UPDATE`;
  a timer checks 10 s after start and then when 24 h have passed; `WM_ENDSESSION`
  closes the window so Restart Manager can replace the exe.
- Background check failures are logged, not shown; a failure after a click is shown.

## Findings / gotchas

- **The release key:** ID `F458D6C29DBD2C05`, public key
  `RWQFLL2dwtZY9DF+FMseD0gj8++iXgURRbysZlwxPPzFowjJEgtnWcAx` (`minisign.pub`). Secret,
  unencrypted, only at `C:\Users\camer\.minisign\open-task.key` until it becomes the
  `MINISIGN_SECRET_KEY` secret. Test fixtures use a separate throwaway key whose
  secret was never kept (`crates/ot-update/testdata/test.pub`).
- **The hand-written `.res` is byte-identical to `rc.exe`'s** (Windows Kits
  10.0.26100, `/l 0x409`) for the same VERSIONINFO. PowerShell's
  `(Get-Item exe).VersionInfo` reads every field; `IsPreRelease` is set for dev
  builds.
- **`git describe --dirty` takes the index lock** (it refreshes the index), which
  could fail another thread's `git add` in the shared tree during any build. The
  build script uses `describe` without `--dirty` plus `status --porcelain
  --untracked-files=no` with `GIT_OPTIONAL_LOCKS=0`: read-only.
- A no-op rebuild stays `Fresh`: `rerun-if-changed` only lists paths that exist
  (a missing `packed-refs` would force a re-run every build).
- **`cargo remove` garbage-collects unused `[workspace.dependencies]`**: removing a
  stray dev-dependency from `ot-update` also deleted the (unused) `ot-record` and
  `ot-update` workspace entries. Restored from HEAD.
- **Git Bash `sed -i` strips the CRs** from a CRLF file; use Python with
  `newline=""` or the Edit tool. `rustfmt.toml` has `newline_style = "Windows"`.
- `sha2` 0.11 no longer implements `std::io::Write`; hashing uses a read loop.
- WinHTTP's error codes (12002, 12007, 12029, ...) have no text in the system message
  table; `imp/windows.rs` spells out the common ones.
- Live check against GitHub (2026-09-28): `--check-update` and the app's "Check now"
  both report "the latest release is not signed, or there is none": v0.2.1 has no
  `SHA256SUMS.minisig`, so `latest/download/SHA256SUMS.minisig` is a 404. The network
  test (`cargo test -p ot-update -- --ignored`) fetches v0.2.1's `SHA256SUMS`
  through GitHub's redirect, and gets 404 and the size limit right.
- Inno's `setup.exe` stub is `asInvoker` (checked in a built installer's manifest), so
  `std::process::Command` starts it and Setup elevates itself.
- **A command-line `/CURRENTUSER` wins over an existing all-users install** (Inno
  source, `Setup.MainFunc.pas`, `HandlePrivilegesRequiredOverrides`: with
  `PrivilegesRequiredOverridesAllowed=commandline` the command line sets the mode;
  `UsePreviousPrivileges` only applies to the dialog). So a per-user test install
  never touches the Program Files copy.
- Ubuntu 24.04 (`ubuntu-latest`) has minisign 0.11-1 in universe; 0.11 is the first
  version with password-less keys (`-W`). The workflow strips `\r` from the secret,
  since the key file was written on Windows.
- **End-to-end update passed (2026-09-28)**, per-user, on this machine, with the user's
  Program Files install and its two running instances untouched:
  1. Two release builds of `9efd436` with `OT_UPDATE_FEED=http://127.0.0.1:8765/releases`
     (the second with a trailing `/`, so its bytes differ) and `OT_UPDATE_PUBLIC_KEY`
     = the test key, `CARGO_TARGET_DIR=target/e2e`. Installers from each (0.2.1 and
     0.3.0) with the portable Inno 6.7.3 (`INNO_SETUP_DIR=...\target\tools\innosetup6`).
  2. Feed in `%TEMP%\e2e\feed\releases\{latest,download/v0.3.0}` with `SHA256SUMS`
     and its signature (test key, comment `open-task v0.3.0`), served by
     `python -m http.server 8765 --bind 127.0.0.1`.
  3. Old installer `/VERYSILENT /SUPPRESSMSGBOXES /NORESTART /CURRENTUSER`:
     `--check-update` said "installed for User in ...\Programs\open-task\" and "v0.3.0
     is available".
  4. `%TEMP%\e2e\e2e.ps1` (scratch) launched it, posted a click on the rail button:
     check, download and verify in 0.23 s, "Install v0.3.0". Second click: Setup
     started, the app logged `WM_ENDSESSION` reason 1 (`ENDSESSION_CLOSEAPP`) and
     exited 0, Setup installed and started the new build (new PID) with

     the download folder was empty afterwards.
  5. The feed saw only: `latest/download/SHA256SUMS.minisig`,
     `download/v0.3.0/SHA256SUMS`, the installer once.
  6. Uninstalled silently: no HKCU key, folder or Start Menu entry left.
- **Install on close passed end to end (2026-09-28)**, same per-user setup with
  `06876ea`, `InstallUpdates`/`DownloadUpdates`/`CheckForUpdates` set to 1 for the
  test and removed after (the `HKCU\Software\open-task` key did not exist before and

- **Not exercised end to end:** the all-users (`/ALLUSERS`) path, to keep the user's

- Existing tags `v0.2.0`, `v0.2.1` are annotated; `--tags` covers lightweight ones too.
- This Claude session runs elevated (High integrity): installs here never show UAC,

- Inno exit codes: 0 ok, 1 init failed, 2 cancelled before install, 3/4 fatal, 5

- Inno writes `InstallLocation` with a trailing backslash
